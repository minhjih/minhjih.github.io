# 잔열(殘熱) 공연 티켓 QR 시스템 — 설정 가이드 🎟🔥

주소: **https://minhjih.github.io/ticket_2026_Janyeol/**

무엇을 하나요?

1. 관객이 **구글 로그인** → 티켓 예매(계좌이체 / 카카오페이)
2. 관리자가 입금을 확인하면 → 관객 화면에 **입장 QR이 실시간으로 자동 표시**
3. 입구에서 확인자가 **QR을 스캔**하면 입장 처리 + 그 QR은 **즉시 만료**(재사용 불가)

전부 모바일 최적화되어 있고, 포스터/큐시트가 메인에 노출됩니다.

## 구성

| 파일           | 역할                                                  |
| -------------- | ----------------------------------------------------- |
| `index.html`   | 관객용 — 포스터·큐시트·로그인·예매·내 QR               |
| `admin.html`   | 관리자용 — 입금 확인 / QR 발급 / 매출 집계             |
| `performer.html`| 공연자(밴드)용 — 무료 초대 신청 / 승인 후 입장 QR      |
| `roster.html`  | 예매자 명단 조회(읽기 전용) — 수정 권한 없음           |
| `check.html`   | 확인자(입구)용 — QR 스캔 / 입장 처리                   |
| `config.js`    | 공연 정보·계좌·카카오·포스터 경로 설정                 |
| `img/`         | 포스터 이미지 넣는 곳 (README 참고)                    |

백엔드는 **Supabase**(기존 서울브레멘과 같은 프로젝트 `gppwawgyoysctikujmed`)를 씁니다.

- 테이블: `tk_orders`(주문/QR), `tk_config`(비밀번호) — 이미 생성됨
- 엣지 함수: `janyeol-desk` — 입금확인/체크인 처리 — 이미 배포됨

Apple Wallet 패스 발급은 Supabase 배포 권한 없이 운영할 수 있도록 별도 Vercel Function으로 분리되어 있습니다.
설정과 인증서 배포 방법은 [`wallet-api/README.md`](../wallet-api/README.md)를 참고하세요.

## ✅ 지금 꼭 해야 하는 것 (2가지)

### 1) 구글 로그인 켜기 (Supabase)

Supabase 대시보드 → **Authentication → Sign In / Providers → Google**

1. **Enable** 켜기
2. Google Cloud Console에서 OAuth 클라이언트(웹) 만들고 **Client ID / Secret** 입력
   - 승인된 리디렉션 URI에 아래 추가:
     `https://gppwawgyoysctikujmed.supabase.co/auth/v1/callback`
3. Supabase → **Authentication → URL Configuration → Redirect URLs** 에 추가:
   - `https://minhjih.github.io/ticket_2026_Janyeol/**`

> 이미 구글 로그인이 켜져 있다면 Redirect URLs 에 위 주소만 추가하면 됩니다.

#### (권장) supabase.co 화면 안 보이게 — 네이티브 구글 로그인

기본 방식은 로그인 중간에 `xxxx.supabase.co` 도메인을 잠깐 거쳐서 낯설게 보일 수 있어요.
Google Cloud의 **웹 클라이언트 ID**(`xxxxx.apps.googleusercontent.com`)를 `config.js` 의
`GOOGLE_CLIENT_ID` 에 넣으면, **우리 사이트에서 바로 구글 계정 선택창**이 떠서 supabase.co 가 노출되지 않습니다.

- 조건: Google Cloud → 해당 OAuth 클라이언트 → **승인된 자바스크립트 원본**에 `https://minhjih.github.io` 가 있어야 함(위에서 이미 설정).
- `GOOGLE_CLIENT_ID` 를 비워두면 기존 리다이렉트 방식으로 폴백(로그인은 됨).

### 2) `config.js` 채우기

`config.js` 를 열어 실제 정보로 수정 → 깃허브에 커밋/푸시:

- `BANK`: 입금 받을 **은행 / 계좌번호 / 예금주**
- `TRANSFER.qrImage`: 뱅킹앱 송금 QR 이미지(`img/transfer-qr.png`). 넣으면 예매 화면에 QR이 뜨고, 관객이 토스·카카오뱅크 등으로 스캔해 송금(없어도 계좌번호로 동작)
- `EVENT.price`: 티켓 가격(기본 7,000원), `maxQuantity`: 1인 최대 매수
- 메인 포스터는 `img/poster-main.jpg` 로 포함되어 있습니다. 교체하려면 같은 경로에 덮어쓰세요.
  (선택) 곡별 상세 큐시트 이미지를 `img/poster-cue.jpg` 로 넣으면 타임테이블 위에 함께 표시됩니다. 없어도 큐시트는 텍스트로 나옵니다.

## 운영 흐름

1. 관객: 링크 접속 → 구글 로그인 → 예매(이름·**연락처(필수)**·수량·결제방법·입금자명) → **① 입금하기 → ② 입금 완료** 버튼
   - ‘입금 완료’를 누르면 **완료 시각이 기록**됩니다. 동명이인이 있어도 (이름 + 연락처 + 입금완료 시각)으로 구분돼요.
2. 관리자: `admin.html` → “확인대기” 목록(입금완료 신고건이 위로 정렬) → **입금자명·금액·연락처 대조** → **입금확인 → QR 발급**
3. 관객: 별도 조작 없이 화면에 **입장 QR 자동 등장** (실시간)
4. 입구: `check.html` → 카메라로 QR 스캔 → 입장 / 이미사용 / 무효 즉시 표시, 유효 QR은 만료

> 입금 대사는 **관리자가 직접** 합니다(개인 계좌·카카오페이는 자동 조회가 불가). 대신 구매자의 ‘입금 완료’ 시각·연락처로 대조가 쉬워지고, 목록에서 신고건이 우선 표시됩니다.

### 입금확인 시 이메일 자동 발송 (선택 · 무료)

관리자가 **입금확인(=QR 발급)** 을 누르면, 구매자의 **구글 로그인 이메일**로
"입장 티켓(QR) + 예매 링크"가 자동 발송되게 할 수 있어요. (구글 Apps Script, 무료)

1. [script.google.com](https://script.google.com) → 새 프로젝트 → **`mail-apps-script.gs`** 내용 붙여넣기
2. 맨 위 `ADMIN_KEY` 를 **관리자 비밀번호와 동일하게** 맞추기
3. **배포 → 새 배포 → 웹 앱** (실행: 나 / 액세스: 모든 사용자) → 권한 허용(Gmail 발송) → `/exec` URL 복사
4. **관리자 페이지 → "이메일 알림"** 버튼에 그 URL 붙여넣기 (내부적으로 `tk_config.mail_webhook` 에 저장)

- 발송량 한도: 개인 Gmail 하루 약 100통(Workspace ~1,500통). 발신자는 스크립트 만든 구글 계정.
- URL 을 비우면(또는 미설정) 이메일은 발송되지 않고, 나머지 기능은 그대로 동작합니다.
- 예매 화면 곳곳에 "입금 확인되면 이메일로 알려드려요 — 이메일 확인" 안내가 표시됩니다.

### 예매 / 현매

- **예매(online)**: 위 온라인 흐름(구글 로그인 → 예매 → 입금확인 → QR).
- **현매(onsite)**: 당일 현장에서 현금 결제하는 관객. `check.html`(확인자 페이지) 하단 **‘현매 추가’** 에서 이름·인원(연락처 선택)을 입력하면 **즉시 입장 처리 + 명단에 ‘현매’로 기록**됩니다(계정/QR 불필요).
- **공연자(performer)**: 밴드/공연자 초대 입장. `performer.html` 에서 **구글 로그인 → 이름 + 소속 밴드 선택 → 신청**(무료). 관리자가 승인하면 입장 QR이 자동 발급됩니다. 관리자 화면 **‘공연자’ 탭**에서 신청을 확인·승인하고, 통계에는 **공연자 N인**으로 별도 표시되며 **공연 정산(매출·유료 인원)에는 포함되지 않습니다.** 밴드 목록은 `config.js` 의 `PERFORMER.bands` 에서 수정합니다.
- 관리자 화면·CSV에서 각 건이 **예매/현매/공연자**로 구분되고, 통계에 **예매 N인 · 현매 N인 · 공연자 N인**이 표시됩니다.

### 명단 조회 (읽기 전용)

- `roster.html` — **예매자 명단만 볼 수 있는 읽기 전용 페이지.** 수정·발급·입장 처리 권한이 전혀 없습니다(조회 전용).
- **별도의 ‘명단 보기’ 비밀번호**(`tk_config.view_key`)로 접근합니다. 관리자/확인자 비밀번호와 분리되어 있어, 이 비밀번호를 공유해도 목록 조회 외에는 아무 것도 할 수 없습니다.
- 비밀번호는 **관리자 페이지 → “명단보기 비번”** 버튼으로 설정/변경합니다. (초기값이 설정되어 있으니 배포 전 한 번 바꿔주세요.)
- 이름·구분(예매/현매/공연자)·인원·상태·연락처·시각을 표로 보여주고, 검색/필터/요약을 제공합니다. QR 토큰 등 민감정보는 제외됩니다.

## 자주 묻는 질문

- **로그인 버튼을 눌러도 안 돼요** → 위 “구글 로그인 켜기”의 Redirect URLs / Google 콘솔 리디렉션 URI 확인.
- **QR이 안 떠요** → 관리자 페이지에서 해당 주문을 “입금확인”했는지 확인. (pending 상태면 대기중)
- **카메라가 안 열려요** → `https://` 접속(깃허브 페이지는 기본 https) + 브라우저 카메라 권한 허용. iOS는 Safari 권장.
- **QR을 잘못 만료시켰어요** → 관리자 페이지에서 해당 “입장완료” 주문 → “되돌리기”로 다시 발급 가능.
- **환불/취소** → 관리자 페이지에서 주문 “취소”.

## 보안 메모

- 관객은 자신의 주문만 조회/생성 가능(Row Level Security). 다른 사람 QR을 볼 수 없습니다.
- 입금확인·체크인 같은 민감한 처리는 서버(엣지 함수)에서만 실행되고, 비밀번호로 보호됩니다.
- QR 토큰은 무작위 UUID이며, 체크인 시 원자적으로 1회만 소비됩니다(동시 스캔 이중입장 방지).
