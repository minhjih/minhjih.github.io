# 잔열(殘熱) 공연 티켓 QR 시스템 — 설정 가이드 🎟🔥

주소: **https://minhjih.github.io/ticket_2026_Janyeol/**

무엇을 하나요?

1. 관객이 **구글 로그인** → 티켓 예매(계좌이체 / 카카오페이)
2. 관리자가 입금을 확인하면 → 관객 화면에 **입장 QR이 실시간으로 자동 표시**
3. 입구에서 확인자가 **QR을 스캔**하면 입장 처리 + 그 QR은 **즉시 만료**(재사용 불가)

전부 모바일 최적화되어 있고, 포스터/큐시트가 메인에 노출됩니다.

## 구성

| 파일           | 역할                                                  |
| -------------- | ----------------------------------------------------- |
| `index.html`   | 관객용 — 포스터·큐시트·로그인·예매·내 QR               |

- 테이블: `tk_orders`(주문/QR), `tk_config`(비밀번호) — 이미 생성됨
- 엣지 함수: `janyeol-desk` — 입금확인/체크인 처리 — 이미 배포됨

## ✅ 지금 꼭 해야 하는 것 (2가지)

### 1) 구글 로그인 켜기 (Supabase)

Supabase 대시보드 → **Authentication → Sign In / Providers → Google**

1. **Enable** 켜기
2. Google Cloud Console에서 OAuth 클라이언트(웹) 만들고 **Client ID / Secret** 입력
   - 승인된 리디렉션 URI에 아래 추가:
     `https://gppwawgyoysctikujmed.supabase.co/auth/v1/callback`
3. Supabase → **Authentication → URL Configuration → Redirect URLs** 에 추가:
   - `https://minhjih.github.io/ticket_2026_Janyeol/**`

> 이미 구글 로그인이 켜져 있다면 Redirect URLs 에 위 주소만 추가하면 됩니다.

### 2) `config.js` 채우기

`config.js` 를 열어 실제 정보로 수정 → 깃허브에 커밋/푸시:

- `BANK`: 입금 받을 **은행 / 계좌번호 / 예금주**
- `TRANSFER.qrImage`: 뱅킹앱 송금 QR 이미지(`img/transfer-qr.png`). 넣으면 예매 화면에 QR이 뜨고, 관객이 토스·카카오뱅크 등으로 스캔해 송금(없어도 계좌번호로 동작)
- `EVENT.price`: 티켓 가격(기본 7,000원), `maxQuantity`: 1인 최대 매수
- 메인 포스터는 `img/poster-main.jpg` 로 포함되어 있습니다. 교체하려면 같은 경로에 덮어쓰세요.
  (선택) 곡별 상세 큐시트 이미지를 `img/poster-cue.jpg` 로 넣으면 타임테이블 위에 함께 표시됩니다. 없어도 큐시트는 텍스트로 나옵니다.

## 운영 흐름

1. 관객: 링크 접속 → 구글 로그인 → 예매(이름·**연락처(필수)**·수량·결제방법·입금자명) → **① 입금하기 → ② 입금 완료** 버튼
   - ‘입금 완료’를 누르면 **완료 시각이 기록**됩니다. 동명이인이 있어도 (이름 + 연락처 + 입금완료 시각)으로 구분돼요.
2. 관리자: `admin.html` → “확인대기” 목록(입금완료 신고건이 위로 정렬) → **입금자명·금액·연락처 대조** → **입금확인 → QR 발급**
3. 관객: 별도 조작 없이 화면에 **입장 QR 자동 등장** (실시간)
4. 입구: `check.html` → 카메라로 QR 스캔 → 입장 / 이미사용 / 무효 즉시 표시, 유효 QR은 만료

> 입금 대사는 **관리자가 직접** 합니다(개인 계좌·카카오페이는 자동 조회가 불가). 대신 구매자의 ‘입금 완료’ 시각·연락처로 대조가 쉬워지고, 목록에서 신고건이 우선 표시됩니다.

### 예매 / 현매

- **예매(online)**: 위 온라인 흐름(구글 로그인 → 예매 → 입금확인 → QR).
- **현매(onsite)**: 당일 현장에서 현금 결제하는 관객. `check.html`(확인자 페이지) 하단 **‘현매 추가’** 에서 이름·인원(연락처 선택)을 입력하면 **즉시 입장 처리 + 명단에 ‘현매’로 기록**됩니다(계정/QR 불필요).
- 관리자 화면·CSV에서 각 건이 **예매/현매**로 구분되고, 통계에 **예매 N인 · 현매 N인**이 표시됩니다.

## 자주 묻는 질문

- **로그인 버튼을 눌러도 안 돼요** → 위 “구글 로그인 켜기”의 Redirect URLs / Google 콘솔 리디렉션 URI 확인.
- **QR이 안 떠요** → 관리자 페이지에서 해당 주문을 “입금확인”했는지 확인. (pending 상태면 대기중)
- **카메라가 안 열려요** → `https://` 접속(깃허브 페이지는 기본 https) + 브라우저 카메라 권한 허용. iOS는 Safari 권장.
- **QR을 잘못 만료시켰어요** → 관리자 페이지에서 해당 “입장완료” 주문 → “되돌리기”로 다시 발급 가능.
- **환불/취소** → 관리자 페이지에서 주문 “취소”.

## 보안 메모

- 관객은 자신의 주문만 조회/생성 가능(Row Level Security). 다른 사람 QR을 볼 수 없습니다.
- 입금확인·체크인 같은 민감한 처리는 서버(엣지 함수)에서만 실행되고, 비밀번호로 보호됩니다.
- QR 토큰은 무작위 UUID이며, 체크인 시 원자적으로 1회만 소비됩니다(동시 스캔 이중입장 방지).
